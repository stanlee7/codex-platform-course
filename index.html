기획부터 배포까지
한 번에 경험하는 플랫폼 제작

Codex를 활용해 간단한 웹 플랫폼을 설계하고 구현한 뒤 GitHub와 Vercel을 이용해 실제 서비스 URL까지 만들어 봅니다. 백엔드는 깊게 개발하지 않고 Supabase와 Railway의 역할과 연결 구조를 이해하는 수준으로 다룹니다.

01. 기획

아이디어를 PRD와 사용자 흐름으로 구체화합니다.

02. 구현

Codex와 대화하며 프론트엔드를 단계별로 만듭니다.

03. 배포

GitHub에 코드를 올리고 Vercel로 공개합니다.

전체 개발 흐름

강의에서는 이 순서를 반복해서 강조합니다. 기능보다 흐름을 익히는 것이 핵심입니다.

환경설치→ PRD→ 구조설계→ 디자인→ Codex 구현→ GitHub→ Vercel
추천 실습 범위
로그인, 결제, 관리자 기능까지 한 번에 만들기보다 첫 수업에서는 검색, 카드 목록, 필터, 상세 페이지, 폼 UI 정도까지 구현하는 것이 좋습니다.

Python은 꼭 필요한가?
프론트엔드만 제작하는 수업이라면 필수는 아닙니다. HTML, CSS, JavaScript, React, Next.js 중심이라면 Node.js가 핵심입니다. Python은 이후 FastAPI, 데이터 가공, AI 모델 연결 수업으로 확장할 때 설치해도 됩니다.

구조 설계와 디자인

디자인부터 시작하지 말고 구조를 먼저 정한 뒤 화면 스타일을 결정합니다.

Figma

직접 와이어프레임과 UI를 만들고 싶은 경우 적합합니다. 화면별 세부 조정과 협업에 강합니다.

Google Stitch

STEP 04

Codex로 프론트엔드 구현

수업에서는 한 번에 전부 만들라고 하지 말고 작은 단위로 요청하는 것이 안정적입니다.

추천 스택

방식추천 대상장점
HTML + CSS + JavaScript완전 초급구조가 단순하고 원리를 이해하기 쉬움
Vite + React플랫폼 UI 실습컴포넌트 구조를 경험하기 좋음
Next.js실제 서비스 확장배포, 라우팅, 서버 기능 확장이 편리함
강의 추천
첫 실습은 Vite + React 또는 Next.js 중 하나만 고정하는 것이 좋습니다. 여러 프레임워크를 동시에 보여주면 설치와 오류 대응에 시간이 많이 소모됩니다.

예시: Vite + React 시작

npm create vite@latest my-platform
cd my-platform
npm install
npm run dev

Codex 구현 순서

  1. 프로젝트 전체 구조 생성
  2. 공통 레이아웃 구현
  3. 더미 데이터 생성
  4. 카드와 목록 구현
  5. 검색과 필터 구현
  6. 상세 화면 구현
  7. 반응형 수정
  8. 오류 점검과 코드 정리

STEP 05

GitHub에 업로드

Git은 코드를 저장하는 도구가 아니라 코드의 변경 이력을 관리하는 도구입니다.

가장 기본적인 흐름

git init
git add .
git commit -m "first commit"
git branch -M main
git remote add origin https://github.com/사용자명/저장소명.git
git push -u origin main

이후 수정할 때

git add .
git commit -m "update ui"
git push
주의
API Key, 비밀번호, 서비스 비밀키는 GitHub에 올리지 않습니다. 실제 프로젝트에서는 .env 파일과 환경변수 관리가 중요합니다.
STEP 06

Vercel로 배포

GitHub 저장소를 Vercel에 연결하면 프론트엔드 프로젝트를 실제 URL로 공개할 수 있습니다.

GitHub 저장소→ Vercel Import→ Build→ Deploy→ 공개 URL

배포 전 체크

  • 로컬에서 npm run dev가 정상 실행되는가?
  • 빌드 명령이 정상 작동하는가?
  • 모바일 화면이 깨지지 않는가?
  • 콘솔 오류가 없는가?
  • GitHub 최신 코드가 push 되었는가?

배포가 실패하면 확인할 것

  • Build Command 오류
  • 패키지 설치 오류
  • 잘못된 import 경로
  • 환경변수 누락
  • 대소문자 파일명 불일치
STEP 07

백엔드는 여기까지만 이해하기

이번 수업에서는 직접 구현보다 프론트엔드 뒤에서 어떤 일이 필요한지 이해하는 것이 목적입니다.

Supabase

Postgres 데이터베이스, 인증, 스토리지, API 기능을 빠르게 붙일 수 있는 백엔드 플랫폼입니다.

Database Auth Storage API

Railway

API 서버나 장시간 실행되는 백엔드 서비스를 배포할 때 사용할 수 있는 클라우드 배포 플랫폼입니다.

FastAPI Node API Worker Docker

구조를 그림으로 이해하기

사용자 브라우저
      ↓
프론트엔드
Vercel
      ↓
API 요청
      ↓
백엔드
Supabase 또는 Railway
      ↓
데이터베이스 / 인증 / 연산

언제 Supabase가 필요한가?

  • 사용자 회원가입과 로그인이 필요할 때
  • 사용자가 입력한 데이터를 저장해야 할 때
  • 여러 사용자가 같은 데이터를 공유해야 할 때
  • 이미지나 파일을 저장해야 할 때

언제 Railway가 필요한가?

  • Python FastAPI 서버를 실행해야 할 때
  • 복잡한 계산과 데이터 가공이 필요할 때
  • 외부 API를 서버에서 안전하게 호출해야 할 때
  • 백그라운드 작업이나 별도 서버 프로세스가 필요할 때
이번 강의의 기준선
백엔드는 연결 원리까지만 설명하고 실제 실습은 프론트엔드 배포에서 종료합니다. 이후 심화 과정에서 Supabase, FastAPI, Railway를 각각 별도 실습으로 분리하는 것이 좋습니다.

최종 실습 과제

상태 카드, 진행률, 일정 UI, 필터

개인 포트폴리오 플랫폼

프로젝트 목록, 경력, 상세 사례, 문의 폼

최종 제출 조건

  • PRD 문서가 있다.
  • 사이트맵 또는 화면 구조가 있다.
  • Codex로 프로젝트를 생성했다.
  • 최소 3개 이상의 UI 기능이 작동한다.
  • 모바일 화면이 대응된다.
  • GitHub 저장소에 코드가 올라가 있다.
  • Vercel 공개 URL이 생성되어 있다.
